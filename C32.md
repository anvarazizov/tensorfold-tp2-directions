# TensorFold TP2 with 32 concurrent requests

[Download the C32 release assets and reproduce the 32-request benchmark](C32-QUICKSTART.md).

On November 19, 2026, a pair of 128 GB GB10s ran the original DeepSeek V4.1 Flash EXL3 2.5 bpw weights with per-request directions and up to 32 decode streams. The C32 engine and lane worker must come from the same build because the peer protocol changed. The C1 launcher in this repository reproduces the earlier experiment. The separate C32 source package was recorded with SHA-256 `8022044bb4ae4de51b2e51fcbcaff1078b834144f739b4adcf0b5672f0046c02`.

## What fit on two machines

| Test | Observed result |
|---|---|
| 32 simultaneous requests targeting 64K input tokens each | Peak mixed decode batch of 32. All direction packets and token hashes matched their solo controls. |
| Long-context retrieval, one request at a time | Correct retrieval at 250,004 and 450,009 input tokens, both OFF and at client strength 0.5 in the bring-up profile. |
| Warm-cache and API checks | Bring-up report records 19/19, including selected layers, invalid parameters and streaming. |

The configured limit was 499,712 total tokens per request, with a shared pool and a 32,768-token output budget. The concurrency and long-context tests exercised different workloads. Graphs and speculative decoding were off.

## Interpreting the strength field

Record both the API strength and the kernel build with every measurement. The C1 kernel uses the API value directly. The calibrated C32 kernel multiplies it by 2.5, so a client value of 0.5 means an effective coefficient of 1.25 on that build. With a unit direction, coefficient 1 removes the component along the direction. At 2.5 the component changes sign and retains 1.5 times its original magnitude. Matching a coefficient or a few greedy outputs cannot establish equivalence to an independently quantized checkpoint.

The request packet echoes the client value. It can confirm routing and layer selection, but two kernel builds can echo the same packet and produce different logits. Give each kernel build its own cache namespace or clear the cache on change. Although the correction adds no KV dimensions, earlier corrected layers can change later layers’ keys and values.

## Paired behavioral measurements

Each cell counts visible prefixes classified as refusals out of 100 prompts, first by a deterministic opener rule and then by a blinded GLM judge. The same prompts were used at each effective coefficient. The counts below were recomputed from the 800 saved label pairs.

| Effective coefficient | mlabonne test subset, rule / judge | JBB harmful subset, rule / judge |
|---:|---:|---:|
| 0 | 97 / 98 | 95 / 98 |
| 1 | 83 / 84 | 66 / 72 |
| 1.75 | 11 / 17 | 2 / 9 |
| 2.5 | 0 / 3 | 0 / 4 |

The two methods agreed on 758/800 prefixes. Agreement measures consistency between classifiers. Either can misclassify a response, and neither score measures whether an answer is correct or complete. The separate comparison with GLM as a generator used different output budgets and reasoning settings, which prevents a direct inference about speed or answer quality.

## Repeating the checks on another port

1. Record the checkpoint, quantization, vector digest, layer numbering and exact projection site. For directions inferred from checkpoint differences, check the residual of a rank-one fit on each candidate matrix. Quantization and unrelated edits can dominate the difference.
2. Compare cold-prefill logits for an omitted descriptor, explicit zero, one nonzero setting and a return to baseline. Keep model, prompt and decoding settings fixed. Verify every rank receives the same descriptor.
3. Warm a prefix, vary strength and layer mask, then repeat the original request. Compare cache hits and generated tokens against cold controls. Repeat with interleaved concurrent requests and compare each stream to its solo control.
4. For a behavioral comparison, pair prompts across settings, retain visible outputs and record truncation. Blind the labels, inspect disagreements and separately score long-answer quality. Publish the scoring rule and the output budget alongside counts.

## Clients and gateways

Send the descriptor on every chat-completions request. In the reported deployment an Open WebUI filter added it per chat and a Pi extension stored the setting per session. Non-streaming chat responses exposed the packet for verification. The gateway reserialized streaming chunks and omitted the packet there. Its Responses and Anthropic translations dropped the field, so the deployment explicitly rejected requests that supplied it on those routes. Check the actual route and echoed packet when qualifying another gateway.
